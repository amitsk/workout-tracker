# Database Schema Documentation

**Variant**: minimal-workouts  
**PostgreSQL**: 14+  
**Document Version**: 1.2  
**Last updated**: 2026-09-02

## Overview

The Weight Training Workout Tracker stores user accounts, an exercise catalog (system defaults plus user-custom exercises), workout sessions, and per-set load. Five tables, audit timestamps, foreign-key constraints, and index optimizations designed for rapid, low-latency logging.

This is intentionally small and optimized for a < 1-week MVP build. It is **not** the comprehensive activity-tracker schema (`comprehensive-workouts/`). It avoids unnecessary abstractions while retaining rock-solid relational integrity.

## Design Principles & v1.2 Optimizations

- **Simplicity**: Exactly five core tables needed to log weight training effectively.
- **SQL-Standard Identity**: Uses `BIGINT GENERATED BY DEFAULT AS IDENTITY` instead of legacy PostgreSQL `BIGSERIAL`.
- **Per-set Truth**: Weight, reps, and warmup flags live on `workout_sets`. Real-world training (pyramid, drop, backoff, and warmup sets) is faithfully represented.
- **Session Duration & State**: `sessions` includes `started_at` and optional `ended_at` with a check constraint (`ended_at >= started_at`). Workouts can be logged as in-progress (`ended_at IS NULL`) or completed.
- **Catalog Safety**: System exercises (`user_id IS NULL`) are shared and cannot be griefed or deleted by users. Lifters can add custom exercises (`user_id = <user_id>`).
- **Index Optimization**: Avoids redundant indexing on `workout_sets(workout_id)` since the `UNIQUE(workout_id, set_number)` constraint already creates a B-Tree index with `workout_id` as the leading column.
- **Audit Trail**: Every table has `created_at` and `updated_at` (`TIMESTAMPTZ`), with `updated_at` automatically maintained by a reusable database trigger.
- **Referential Integrity**: Cascading deletes for user accounts and sessions; `ON DELETE RESTRICT` on exercise types to prevent breaking historical records.

## Entity Relationship

```
users 1──N sessions 1──N workouts 1──N workout_sets
  │
  └──0..N workout_types (user custom)
            ▲
            │ N──1
         workouts
```

## Tables

### 1. `users`

Registered accounts.

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `user_id` | `BIGINT` | PK, GENERATED IDENTITY | Unique user identifier |
| `name` | `VARCHAR(255)` | NOT NULL, not blank | Display name |
| `email` | `VARCHAR(255)` | NOT NULL, UNIQUE (indexed) | Login identity; stored lowercase and trimmed |
| `password_hash` | `VARCHAR(255)` | NOT NULL | bcrypt or Argon2 hash; never plaintext |
| `created_at` | `TIMESTAMPTZ` | NOT NULL, default now | Account creation |
| `updated_at` | `TIMESTAMPTZ` | NOT NULL, default now | Last profile update |

**Indexes**: PK on `user_id`; UNIQUE index on `email`.

### 2. `workout_types`

Exercise catalog containing shared system exercises and optional user-defined custom exercises.

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `workout_type_id` | `BIGINT` | PK, GENERATED IDENTITY | Unique exercise identifier |
| `user_id` | `BIGINT` | NULLABLE, FK → `users` CASCADE | NULL = system default; non-null = user custom |
| `name` | `VARCHAR(255)` | NOT NULL, not blank | Exercise name |
| `description` | `TEXT` | | Optional instructions or description |
| `created_at` | `TIMESTAMPTZ` | NOT NULL, default now | |
| `updated_at` | `TIMESTAMPTZ` | NOT NULL, default now | |

**Constraints & Indexes**:
- Partial UNIQUE index on `lower(trim(name)) WHERE user_id IS NULL` (prevents duplicate system exercises).
- Partial UNIQUE index on `(user_id, lower(trim(name))) WHERE user_id IS NOT NULL` (prevents duplicate custom exercises for a user).
- Index on `user_id WHERE user_id IS NOT NULL` for fast custom exercise filtering.
- Deleting an exercise referenced by `workouts` is **rejected** (`ON DELETE RESTRICT`).

### 3. `sessions`

One gym visit / training session.

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `session_id` | `BIGINT` | PK, GENERATED IDENTITY | Unique session identifier |
| `user_id` | `BIGINT` | NOT NULL, FK → `users` CASCADE | Owner of the session |
| `started_at` | `TIMESTAMPTZ` | NOT NULL, default now | When the session began |
| `ended_at` | `TIMESTAMPTZ` | CHECK `ended_at >= started_at` | When completed; NULL if in progress |
| `notes` | `TEXT` | | Optional session notes |
| `created_at` | `TIMESTAMPTZ` | NOT NULL, default now | |
| `updated_at` | `TIMESTAMPTZ` | NOT NULL, default now | |

**Indexes**: `(user_id, started_at DESC)` — composite index for the paginated "my sessions" view.

### 4. `workouts`

An exercise block inside a session (e.g., "Squat" as movement #1).

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `workout_id` | `BIGINT` | PK, GENERATED IDENTITY | Unique block identifier |
| `session_id` | `BIGINT` | NOT NULL, FK → `sessions` CASCADE | Parent session |
| `workout_type_id` | `BIGINT` | NOT NULL, FK → `workout_types` RESTRICT | Which exercise was performed |
| `display_order` | `INTEGER` | NOT NULL, default 0, ≥ 0 | Order within the session |
| `notes` | `TEXT` | | Optional block notes (e.g., "Used belt on top set") |
| `created_at` | `TIMESTAMPTZ` | NOT NULL, default now | |
| `updated_at` | `TIMESTAMPTZ` | NOT NULL, default now | |

**Indexes**: `(session_id, display_order)`; `workout_type_id`.

### 5. `workout_sets`

Individual sets for an exercise. This table records the actual training load.

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `workout_set_id` | `BIGINT` | PK, GENERATED IDENTITY | Unique set identifier |
| `workout_id` | `BIGINT` | NOT NULL, FK → `workouts` CASCADE | Parent exercise block |
| `set_number` | `INTEGER` | NOT NULL, > 0; UNIQUE with `workout_id` | 1, 2, 3, … |
| `reps` | `INTEGER` | NOT NULL, > 0 | Repetitions completed |
| `weight` | `NUMERIC(8,2)` | NULL or ≥ 0 | Load. `NULL` (or `0`) means bodyweight |
| `weight_unit` | `VARCHAR(10)` | NOT NULL, default `'kg'`, `IN ('kg','lbs')` | Unit for weight |
| `is_warmup` | `BOOLEAN` | NOT NULL, default `FALSE` | Excluded from working volume / PR calculations |
| `created_at` | `TIMESTAMPTZ` | NOT NULL, default now | |
| `updated_at` | `TIMESTAMPTZ` | NOT NULL, default now | |

**Indexing Optimization**:
`CONSTRAINT workout_sets_unique_number UNIQUE (workout_id, set_number)` provides both uniqueness and a B-Tree index on `(workout_id, set_number)`. Because `workout_id` is the leading key, Postgres uses this index directly for all `workout_id` joins and deletes, avoiding redundant index storage and write amplification.

## Volume and Metrics Guidelines

- **Working Volume**: `SUM(reps * COALESCE(weight, 0)) WHERE is_warmup = FALSE` grouped by `weight_unit`. Never add kg and lbs together.
- **Estimated 1RM (Epley Formula)**: `MAX(weight * (1.0 + reps / 30.0)) WHERE is_warmup = FALSE AND weight IS NOT NULL`.

## Relationships & Delete Behaviors

| Parent | Child | On delete | Rationale |
|--------|-------|-----------|-----------|
| `users` | `sessions` | CASCADE | Account deletion removes personal history |
| `users` | `workout_types` (custom) | CASCADE | Custom exercises deleted with user account |
| `sessions` | `workouts` | CASCADE | Session deletion removes exercises |
| `workouts` | `workout_sets` | CASCADE | Exercise deletion removes sets |
| `workout_types` | `workouts` | **RESTRICT** | Protects historical sessions from broken references |
